# Technical Documentation

## Goal

Help a new developer understand what TensorCheck does, install it, run one example, and interpret the result quickly.

## README Structure

1. one-sentence purpose
2. problem example
3. installation
4. 60-second quickstart
5. example report
6. current scope
7. architecture link
8. research status
9. contributing
10. citation/license when applicable

## Documentation Types

Keep distinct:
- tutorial: learn by doing
- how-to: accomplish a task
- reference: exact API/CLI behavior
- explanation: concepts/design

## Rules

- Every command should be runnable.
- Do not document future features as current.
- Keep output examples synchronized with code.
- Explain failure predicates in plain language.
